## Workspace redesign in progress (feature/lyrics-workspace-maker)

The app now has adaptive Library, Lookup, Maker, and Settings navigation. `WorkspaceDatabase.kt` owns `workspace.db`, a separate Room v1 database for persistent drafts and normalized provider cache. `DraftFormat.kt` converts draft lines and word stamps to portable, enhanced, and text exports. `MakerScreen.kt` hosts text editing, timing, local playback, export, and the explicit SAF embedding path. It reads artwork only from local audio metadata and keeps thumbnails in a bounded memory cache, with generated artwork as fallback. `LookupScreen.kt` searches enabled providers after consent and reuses cache entries for 30 days (found), six hours (missing), or 15 minutes (error). `LibraryWorker.kt` shares this cache with folder scans and inserts discovered rows before inspecting their metadata. The new Room schema is in `app/schemas/com.music.lyricsapp.WorkspaceDatabase/1.json`.

Maker embedding asks for the attached file's parent tree and then calls `ApprovedWriter.apply` with that tree. It does not make the parent tree the library folder. ## Device-wide library and track details (2026-11-05)

`MediaLibrary.kt` queries the MediaStore audio collection after `READ_MEDIA_AUDIO` (Android 13+) or `READ_EXTERNAL_STORAGE` (Android 8–12) is granted. It stores volume-specific content URIs as stable track keys in the existing `lyrics.db` schema and keeps SAF rows and `workspace.db` drafts. When a readable media path identifies an overlapping SAF file, the Library shows its SAF row if it already has lyrics or review work; otherwise it shows the indexed row. Both overlapping rows are excluded from automatic lyric writes. Indexed tracks are loaded without scanning a folder; SAF remains the fallback for unindexed audio. The read permission is requested from the Library button, and legacy writes request `WRITE_EXTERNAL_STORAGE` only at Save.

`MetadataEditorScreen.kt` shows original and edited common tags, local artwork previews, and lyrics. Artwork can come from a picked JPEG/PNG or be copied from another picked audio file; `MetadataWriter.kt` reads its embedded image without modifying that source and holds the selected bytes until Save. The writer prepares a candidate for MP3, FLAC, M4A, or audio MP4 with JAudioTagger 3.0.1 (LGPL); it checks tag values, unrelated raw tag fields, artwork, a standard portable lyrics field, and a format-specific audio-payload digest before requesting access. Other formats are read-only in this editor. For SAF, it writes a tagged sibling and retains the renamed original as a folder backup. For MediaStore, Android 11+ uses a per-file write request, Android 10 uses a recoverable request, and Android 8–9 uses the write permission plus an in-app confirmation. A durable app-private original and record precede any in-place write. A SHA-256 check verifies the written candidate; interrupted or failed writes surface Restore in Needs attention on next launch. `MediaRecovery.kt` keeps those copies under `filesDir/metadata_recovery`, and `RecoveryManager.kt` applies the existing retention setting to both backup types. Metadata Save does not start provider lookup.

The implementation reviewed the GPL-licensed PixelPlayerOSS library, editor, and recovery workflow at `https://github.com/PixelPlayerHQ/PixelPlayerOSS` in a temporary clone; no PixelPlayer code or assets were copied. The proprietary PixelPlayer repository was excluded. `./gradlew :app:assembleDebug` succeeded with `ANDROID_HOME=/home/zoom/android-sdk`. No device was attached, so per-format round trips, permission flows, interrupted writes, restoration, 10k-track performance, and accessibility remain open in `manual-tests.md`. No tests were added or run.

## Project

`app` is the Android/Compose application (`com.music.lyricsapp`), min API 26, target/compile API 36, Java 17. `lyricsCore` holds LRC parsing, matching, and 17 selectable third-party lyric sources. The project is GPL-3.0 and uses no Play Services, Firebase, or analytics SDK. The first-run privacy dialog gates online lookup. Only LRCLIB and lrc.red are selected by default; the user can reorder and enable other sources.

## Main paths

- `MainActivity.kt` coordinates navigation and user actions. `LibraryScreen.kt`, `TrackScreen.kt`, and `SettingsScreen.kt` render the screens; `LyricsTheme.kt` chooses light, dark, system, or dynamic colors.
- `LibraryWorker.kt` scans the user-selected SAF tree, skips recovery artifacts, derives missing artist search hints, observes file signatures, and fetches due sources. It is scheduled on app open/manual rescan and for six-hour constrained background work. `ProviderHealth.kt` tracks backoff and circuit state. `LyricsRepository.kt` applies per-provider timeouts.
- `LyricStore.kt` remains the synchronous SQLite write adapter for `lyrics.db` schema v6. `LyricsRoomDatabase.kt` provides Room Flow reads and explicit migrations from v3–v5. `LyricsViewModel.kt` exposes StateFlow for the UI. Keep the schemas in `app/schemas` when changing the database.
- `LyricConfidence.kt` scores selected results. Automatic writing is off on new installs and requires a score of at least 80, provider agreement, no embedded lyrics, and no Wrong review. `PaxKeyVault.kt` migrates the former plaintext PaxSenix preference to Android Keystore-backed AES-GCM.
- `ApprovedWriter.kt` is the only SAF write path. It checks the scanned signature, copies the original into app cache, checks the standard field and rejects private-only lyrics, writes a separate candidate, verifies the standard field and byte-for-byte candidate transfer, renames the original to a `.lyrics-backup-*` file, then swaps the candidate into the original name. Rename failures leave a clearly named `.tagged-*` candidate and attempt restoration. `RecoveryManager.kt` lists, restores, and manually cleans recovery files. Scans never treat them as library tracks.
- `StandardLyricsField.kt` maps MP3/AAC to ID3 `USLT`, FLAC/Ogg/Opus to Vorbis `LYRICS`, M4A/MP4 to `©lyr`, and WebM/MKV to Matroska `LYRICS`. The supported write paths today are MP3, FLAC, M4A, audio MP4, and WebM. AAC and Ogg/Opus are mapped but **not enabled for writing**. `StandardLyricsReader.kt` reads standard fields for post-write verification; `EmbeddedLyrics.kt` also reads optional private word timing for playback.
